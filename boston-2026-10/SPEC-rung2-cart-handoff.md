# boston-2026-10 — rung 2: a pre-filled cart through the store's tag container. CONTRACT, draft

**Written 2026-09-27. Planned, not started**: it waits on the Owner confirming, at the 2026-10-01 meeting,
that the store's admin exposes a Google Tag Manager container field. Until then rung 1's links stand.

## 0. After this lands, what regenerates it, and from what?

| | what | where | regenerated by |
|---|---|---|---|
| the week's picks (Chef's Choice) | INPUT | `data/picks/<sunday-date>.json` — meal names and counts per plan | a person, weekly, from the Owner's picks |
| the links | OUTPUT | `dist/` | `npm run build` — each result card links to `…/order?mpid=N#fitaf=<payload>` |
| the tag | OUTPUT | `dist/gtm/fitaf-handoff.js` — pasted into a GTM **Custom HTML** tag | `npm run build`; its source is `src/gtm/` |

## 1. The shape

1. The microsite links to `https://fitafnutrition.com/order?mpid=<N>#fitaf=<payload>`. The part after `#`
   never leaves the visitor's browser, and nothing in the store reads it (every query parameter the
   store reads was listed on 2026-09-27; none is a cart).
2. **Without the tag, the link is exactly rung 1** — the plan's order page. The hand-off can only add.
3. **With the tag**, on a page load carrying `#fitaf=`: validate the payload, fill the cart (§ 2), remove
   the fragment, and open `/checkout`. **Any failure: remove the fragment and stop** — the visitor is on
   the plan's order page, as in rung 1. The tag must never leave a half-filled cart.
4. The payload is **meal names and counts, a plan, and an optional offer code** — no prices, no internal
   ids, no personal data. It is short enough for a QR code only if it is a key into a table the tag holds;
   otherwise it is carried by the microsite's link, not the printed code.

## 2. ⛔ The fork: how the tag fills the cart

| | **A — write the store's storage** | **B — press the store's own buttons** |
|---|---|---|
| how | build the cart lines and write `hmp_local_cart` (and `hmp_order_cart_coupon_codes`), then open `/checkout` | wait for the order page to render its meal cards, then use the page's own add controls for each named meal and count, then open `/checkout` |
| needs from us | each line's internal fields — product id, the size add-on ids (Lean `10538`, Signature `10539` in the 2026-09-27 sample), `mpid`, a local id | only meal **names** as the page shows them |
| prices | we must write them, and they must match the store's | ⭐ the store computes them, as for any shopper |
| breaks when | the store changes its storage shape | the store changes its page structure |
| detecting a break | compare the lines we wrote with what the page then shows | a named meal is not found on the page |
| recommendation | | ⭐ **B**: it uses the store's own rules, and it never writes a price. A is the fallback if B's timing proves unreliable |

The offer code, in either case: enter it through the page's own coupon field if one is available before
checkout; write `hmp_order_cart_coupon_codes` only if not — to be proven (§ 4).

## 3. The tag's own rules

- It acts **only** on a `#fitaf=` fragment, on the order page, and **only once** per load. On every other
  page it does nothing — it runs on every page of the store, checkout included.
- It sends **nothing** anywhere and loads nothing else.
- It is under 5 KB, has no dependencies, and is readable: a reviewer can check it in a minute.
- The container it lives in: access limited to named people, two-factor login, and **publishing needs a
  second person's approval** where the account allows it.

## 4. What must be proven, in one browser, with the Advisor watching — nothing submitted

1. The admin's GTM field exists, and the container loads on `fitafnutrition.com`.
2. B: the named meals are found and added at the right size and count; the sidebar and `/checkout`
   agree with the payload. A (if needed): a written cart survives the store's start-up.
3. The offer code applies and the store shows the discount.
4. A payload naming a meal that is not on this week's menu fails safe: no cart change, plain order page.
5. A visit with no fragment is untouched (the tag does nothing).

## 5. Tests — in `node --test`, no network

Payload encode/decode round trip; rejection of a malformed or oversized payload; for B, a fixture DOM of
the order page (saved from a public render) in which the named meals are found, and a mutant fixture
with one meal renamed, in which the tag refuses and changes nothing.
