## 3. `POST /api/save`

Body: `{ kind: "offer" | "expansion", email, zip, consent_marketing, event_id, wording_version, turnstile_token }`.

- **Refusals, named, 400** (no value echoed): `email_invalid` · `zip_invalid` · `event_unknown` ·
  `wording_version_unknown` · `consent_not_boolean` · `kind_invalid` · ⭐ `zip_out_of_area` (kind `offer` with a
  ZIP that is not `in`) · ⭐ `zip_in_area` (kind `expansion` with a ZIP that is `in`) ·
  `consent_marketing_on_expansion` (the marketing box is offer-only). 403 `turnstile_failed`; 429 `rate_limited`.
- **Kind `offer`**: draws a unique offer code (as rung 3); sets `send_at` to **09:00 America/New_York on the
  next calendar day** in that zone (use the Temporal API or `Intl`; a test covers a save at 23:59 and at 00:01
  Eastern, and one across the DST change on 2026-11-01).
- **Kind `expansion`**: no offer code; `send_at` = now (E-X goes at once); `ring` = `near` | `far`.
- ⭐ **Idempotent per `(event_id, kind, lower(email))`**: a second save updates the first (a ticked box becomes
  pending; an unticked box **does not withdraw** an earlier tick; ZIP updated) and never draws a second code.
- **Returns `{ ok: true }` only** — never a code, id or stored value, whether the save was new or repeated.
- The IP is the rate-limit key only; never stored or logged.

## 4. Schema — `migrations/0003_saves.sql`

`saves` (no PII): `save_id` (random) · `event_id` · `kind` (`offer`|`expansion`|`reissue`) · `offer_code`
(UNIQUE, NULL for expansion) · `offer_id` (from `offers.json`) · `ring` (`in`|`near`|`far`) · `reissued_from`
(a `save_id`, for § 5) · `created_at` · `send_at` · `message_state` (`scheduled`|`sent`|`suppressed`|`failed`|
`cancelled`) · `state` (`saved`|`messaged`|`confirmed`|`exported`|`purged`|`lapsed`|`erased`) · `state_at`.

`save_contacts` (the PII, dropped whole, `ON DELETE CASCADE`): `save_id` · `email` NOT NULL · `zip` ·
`consent_marketing` · `consent_expansion` · `wording_version` · `consent_at` · `confirm_token_hash` (SHA-256 of
the token; the token itself is never stored) · `confirmed_at` · `withdrawn_at`.

⛔ No IP, no user agent, no name, no phone, no plan, no calculator values.

## 5. `/confirm/<token>` and `/o/<code>` — Worker-rendered pages

**`/confirm/<token>`** (flows/03 § 5): `GET` renders `LANDING` or `GONE` and **changes nothing**; `POST` with
`action=yes|no` → `CONFIRMED` (sets `confirmed_at`; the save's `state` → `confirmed`) or `DECLINED` (sets
`withdrawn_at`). `GONE` is byte-identical for unknown, expired and purged tokens. Wording: DRAFT § 4. Headers:
`Referrer-Policy: no-referrer`, `Cache-Control: no-store`, `X-Robots-Tag: noindex`. The token is 32 random
bytes, base64url; it is never logged. Token lookups are rate-limited.

**`/o/<code>`** (flows/05 § 3): `ORIGINAL` (code known, its offer live) · `WELCOME_BACK` (code known, offer
expired → the **current** offer, and for a `unique` current offer a **reissued code**: a new `saves` row,
`kind: reissue`, `reissued_from` the original, no contact — **at most one per original per offer**,
idempotent) · `CURRENT` (unknown or malformed: the general offer, **byte-identical** for every unknown code).
Rate-limited.

**`data/offers.json`**: `[{ id, label, applies_to: "event" | "general", valid_from, valid_to, code_mode:
"unique" | "shared", shared_code? }]`, all **placeholders** (`label: "[The offer]"`, `shared_code:
"PLACEHOLDER"`), with a top-level `"status": "placeholder"`. Exactly one `general` offer is current at any
instant; a test checks the file.

## 6. The scheduled Worker (cron, dev: every 5 minutes)

One `scheduled` handler, three steps, each its own module with a unit test:

1. **Send what is due** (`message_state = scheduled`, `send_at <= now`): ask `Redemptions.redeemed(codes)`
   (→ `suppressed`), then `Sender.send(message)`. ⭐ **Null implementations in this rung**: `NullRedemptions`
   returns none; `NullSender` sends nothing and **leaves the message `scheduled`**. The handler reports only
   counts. A `RecordingSender` for tests captures messages, and tests assert E1 and E-X content against DRAFT
   § 3 (placeholders filled from `offers.json`/`events.json`).
2. **Lapse** (flows/06): offer saves without confirmed marketing, 30 days after their offer's `valid_to` →
   delete contact, `lapsed`; expansion saves unconfirmed after 7 days → `lapsed`; confirmed expansion saves
   after `expansion_retention_days` (`data/save.json`, 365, ⬜ proposed) → `lapsed`.
3. **Purge** exported saves (as rung 3's purge; `exported` is reached only by the seeder until the export rung).

A CLI `scripts/erase.mjs --email <address>` (dry run unless `--apply`; refuses any database but
`fitaf-leads-dev`) deletes the contact, cancels an unsent message, sets `erased`.
