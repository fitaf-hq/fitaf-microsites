# The microsite's stories

Each story shows the page exactly as the site's own build writes it (`npm run build` for *production*, the page
eatfitaf.com serves; `npm run build:dev` for *development*, the test address's), built when Storybook starts and shown
in a frame at the width of the chosen viewport (390, the default, or 1280), opened at the page's own fragment, and where
a state needs a press, the story presses the page's own button in the frame as a visitor would; a state a story cannot
reach on the chosen date says so in red in its caption. To name a state in feedback, give its **group · story · width ·
build**, as each caption does: *Individual · Chef's Choice · 390 · production: …*. **The Date control's fixed
clock is the only thing a story adds to a page**: on *a week with picks* and *no picks*, one script before the page's
own starts the frame's clock at noon on that date (the caption names it), so the page chooses that week's Chef's Choice
as it would then; *today* adds nothing. Storybook serves the pages with a policy that refuses any request to another
host (the development page's Turnstile script), so nothing leaves this machine.

## The meal selection

The **Meal selection** stories show the plan page's four questions and what each answer set's card shows: the goal
buttons, the eight answer sets with *No snacks*, and snacks chosen (Q4) with the week's snack list and without one. They open on
the Date control's **fixture week**: a week of invented meal names written as the picks file's version 2, a cart for
every answer set and snacks for every day only, built into the page as the site's build reads any week (its `--picks`),
so every answer set shows its own cart; on a real week most answer sets have none yet and show *Choose your meals* alone.
Each opens scrolled to its subject (the questions, or the snacks). **While snacks are carted** (`data/plans.json`'s
`snacks.carted`), the page offers Q4 only for days the week has a snack list for, so on the fixture week every weekday
answer set shows no Q4, and *or · weekdays · snacks, no list* shows that: Q4 hidden, at the questions; with snacks not
carted, it shows the not-carted line alone. Name a state as *Meal selection · and · weekdays · breakfast · 390: …*.

## The hand-off

The **Hand-off** stories show the hand-off's two faces, the progress screen and the three-step checkout, as the Footer
block ships them: the block is `scripts/build-storefront.mjs`'s own build, made when Storybook starts, running on the
storefront watch's **synthetic store** (`tools/storefront-watch/test/browser-store.mjs`, its page as it serves it) as
the store's Custom Scripts Footer runs it, opened with a test link (`scripts/handoff-link.mjs`'s, the fixture's own
meals), in a frame exactly the viewport's size. Name a state as *Hand-off · Screen · B · 390: …*. The screen is held at
its state by the synthetic store's own options (a planted hang; a route held until the caption's *Release*), and goes
90 s after it came up by its own clock, as on the store: reload the story to see it again. **The checkout is a
stand-in**: it carries the store's names, so its stories show which sections each step shows and hides, the step bar,
Back and Continue, the recap and our words; the store's own fonts, colours and spacing are only on the live store, where
a tweak to how the store's own parts look is still checked. The meals' images are generated tiles (a page colour and the
meal's initial), never a photograph. Nothing presses the pay button, and the store's pages are served with the same
policy, so nothing leaves this machine.
